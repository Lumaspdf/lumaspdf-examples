# LumasPDF SDK examples

Worked examples for the [LumasPDF SDK](https://www.lumaspdf.com), one native PDF
engine with the same C API on Windows, Linux, macOS, iOS and Android.

Each folder is one language binding. Inside it, one folder per example, and
every language carries the same set: the file `hello_world` in `cpp/` does
exactly what `hello_world` in `python/` does, so you can compare bindings side
by side.

| Folder | Binding | Needs |
|---|---|---|
| `c/` | C, flat API | `LumasPdf.dll` / `libLumasPdf.so` + `lumaspdf.h` |
| `cpp/` | C++ (Windows) | same as C |
| `cpp-linux/` | C++ (Linux, CMake) | `libLumasPdf.so` |
| `csharp/` | C# (.NET Framework / .NET) | `LumasPDF.Net.dll` |
| `csharp-nuget/` | C# via the `LumasPDF.Net` NuGet package | `dotnet` |
| `vbnet/` | VB.NET | `LumasPDF.Net.dll` |
| `delphi/` | Delphi, flat DLL unit | `LumasPdf.pas` |
| `delphi-oo/` | Delphi, object-oriented unit | `Lumas.Pdf.pas` |
| `delphi-vcl-static/` | Delphi VCL, statically linked (no DLL) | `LUMAS_STATIC` |
| `python/` | Python 3.8+ (`ctypes`, no compiled module) | `pip install lumaspdf` |
| `php/` | PHP 8 via FFI | `ext-ffi` |
| `vb6/` | Visual Basic 6 | `LumasPdf.dll` |
| `activex/` | ActiveX / COM | `LumasPdfAX32.dll` / `LumasPdfAX64.dll` |

## What the examples cover

Creating pages, text and Unicode, fonts and embedding, images and vector
graphics, tables, form fields (AcroForm and dynamic XFA), annotations,
bookmarks and links, importing and merging existing files, page extraction,
watermarks and stamps, encryption and permissions, digital signatures
(including PAdES and visible signature appearances), incremental updates,
rendering pages to bitmaps, text and image extraction, content parsing,
optimisation, barcodes, PDF/A and PDF/X conversion, ZUGFeRD / Factur-X
e-invoices, and LumasReport report templates (`.lrpt`).

## Running them

1. Download the SDK for your platform from <https://www.lumaspdf.com/download>.
   The download is public and needs no key; unlicensed output carries an
   evaluation watermark. A trial key removes it.
2. Put the engine binary where the example's README or the binding manual
   says, or set `LUMASPDF_DLL` to its path.
3. Build and run the example. Output PDFs land next to the source.

Test fixtures (`test_files/`, images, `.lrpt` templates) are generated by the
SDK's own tooling and carry no third-party content.
