# VB6 examples — ActiveX zero-wrapper conversion (2026-07-20)

All **75/75** VB6 examples converted from the flat DLL wrapper to the registered **ActiveX object**,
with **ZERO wrapper modules**. Verified: every `.vbp` has one `Reference=` line to the LumasPdfAX
type library and zero `Module=LumasPdfApi*` lines; 0 examples still use the flat wrapper.

## The model
```
' .vbp: one Reference line replaces the 5 flat wrapper modules
Reference=*\G{E2FE2B22-5FF6-5275-A6E7-575E68D36DDD}#1.0#0#..\..\..\wrappers\activex\bin32\LumasPdfAX32.dll#LumasPdfAX

' .bas: early-bound OO object; methods + ALL enums + ALL constants from the typelib
Dim pdf As New LumasPdfAX.LumasPDF        ' library=LumasPdfAX, coclass=LumasPDF
pdf.RaiseExceptions = True                ' errors -> VB6 On Error (no callback)
pdf.CreateNewPDFA ""
pdf.SetFontA "Arial", fsItalic, 24#, True, cp1252   ' enums by name (TLB)
pdf.SetFillColor PDF_RED                   ' constants by name (TLB)
```
Flat `pdfFoo(handle, args)` → OO `pdf.Foo args` (drop the `pdf` prefix + the handle). Reference
example: `hello_world`. No `LumasPdf.bas`, no `LumasPdfApi1-4`, no Declares, no AddressOf marshalling.

## Enabling change (made the typelib self-complete)
The AX TLB already exposed all 921 enum members, but was missing the 661 standalone `Public Const`
(colors PDF_*/NO_COLOR, RPT_EXP_*, RPT_FEAT_*, error masks E_*). Added `Emitter.const_members()` in
`tools\gen_axidl.py` → emits them as one `enum LumasPdfConst` in the ridl; rebuilt+re-registered the AX
(x86 `bin32\LumasPdfAX32.dll`). Now an early-bound client needs nothing but the one Reference.

## Callbacks → WithEvents classes
Examples with real callbacks (page-break, ParseContent, rpt custom function/provider, font/ICC) use a
`.cls` with `Public WithEvents Pdf As LumasPdfAX.LumasPDF` + `Private Sub Pdf_OnXxx(...)` handlers
(every event has a trailing ResultCode). Used by: content_parser ×4 (`ParseContentEvents`),
reporting 08/12 (`RptRegisterProviderEvent`/`RptRegisterFunctionEvent`), text_formatting (`OnPageBreak`).

## Results (all built + ran; outputs mostly byte-identical to the flat baseline)
- b1 acroform+annotations 10/10; b2 barcodes/collections/complex_text/content_parser 11/11;
  b3 edit/incremental/layers/merge/metafiles 8/8; b4 optimize/pdf_to_text/checkconformance/pdfviewer/
  rendering 10/10; b5 tables/text/transparency/zugferd 9/9; reporting 01-19 19/19; hello_world +7 stragglers.
- Notable: **text_extraction** (which the flat wrapper FAILED and the .vbs SKIPPED) now WORKS in the
  AX-object VB6 port — VB6 can do COM record marshalling (byte-array OleVariant + CopyMemory) that
  VBScript can't. reporting 13 works plugin-free via the function-event path.
- print_pdf = compile-only (printer). pdfviewer = embedded viewer blocks (PASS).

## Honest VB6-specific limits (worked around with graceful degradation)
- **VB6 cannot early-bind an Int64 (VT_I8) param/return** ("Automation type not supported"). Where a
  method needs one (buffer/64-bit handle), route ONLY that call through a same-instance late-bound alias
  `Dim o As Object: Set o = pdf`.
- I8 **event** params can't be declared in a WithEvents sink → those callbacks dropped (conv_to_zugferd
  font/ICC), same as checkconformance.
- reporting 13's custom **exporter** half omitted: the AX has `RptRegisterFunctionEvent`/`ProviderEvent`
  but no exporter-event, and the raw `rptRegisterExporter` takes an Int64 fn pointer (uncallable early-bound).
  The custom-function half is fully ported. (The FLAT VB6 13 does the exporter via `rptRegisterExporter` + AddressOf.)
- A few flag consts not in the engine's const table (`tfScaleToRect`, `emNoFuncNames`) stay local `Const`.

Per-batch detail: `_AXCONV_*.txt`. The flat wrapper (`LumasPdf.bas` + `LumasPdfApi1-4.bas`) is still
generated by `gen_vb.py` and remains available for xcopy/no-registration deployment, but no example uses it.
